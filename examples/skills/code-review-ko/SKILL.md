# 한국어 코드 리뷰

1. `git diff main...HEAD`(기본 브랜치가 다르면 그것)로 변경 범위를 파악한다.
2. 변경된 파일을 **diff 주변 코드까지** 읽는다. diff만 보고 판단하지 않는다.
3. 아래 순서로 보고한다. 해당 없는 항목은 생략한다.

## 출력 형식
**🔴 버그 가능성** — `파일:줄` · 문제 · 재현 입력/상황 · 수정 제안
**🟡 개선 제안** — 성능, 중복, 에러 처리 누락, 테스트 부족
**🟢 잘한 점** — 한두 줄

## 규칙
- 확실하지 않은 건 "확인 필요"라고 쓰고 단정하지 않는다
- 취향 차이(네이밍, 포맷)는 린터가 잡는 것이면 언급하지 않는다
- 지적마다 **구체적인 줄 번호**를 붙인다
- 코드를 직접 수정하지 않는다. 제안만 한다
